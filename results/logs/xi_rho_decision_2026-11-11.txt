ξ/ρ 边界堆积的口径决策（M3 / T3.8）
日期：2026-11-11        决策人：项目组（M3 提出，Zhou Yixuan 确认）
对应：M3 分工卡 §6 验收项 6、T3.8 兜底预案
数据源：results/logs/xi_rho_by_block.csv、convergence.csv、
        xi_rho_paired_se.csv（1,440 行 = 48 折 × 30 组）、xi_rho_paired_summary.csv（48 行）

一、事实（均由上述 CSV 复算）
- 48 折中，选出的 ξ 落在网格中间 4 个值（0.0010/0.0019/0.0030/0.0050）的有
  33/48 = 68.8%（验收要求 ≥ 90% = 44 折）。
- 堆积是**单侧**的：15 折顶在 ξ = 0.0005（网格最小端，最长记忆），
  **0 折**顶在 0.0080；其余 10 / 7 / 9 / 7 折分别选 0.0010 / 0.0019 / 0.0030 / 0.0050。
- ρ 有两端堆积：20 折在 −0.15、3 折在 +0.15（共 23/48 在边界）。
- 失败折 0/48（B3 与 B4 全部收敛，最大梯度范数 8.6e-1），因此 T3.8 的
  “退到 B3+衰减”**不触发**。

二、证据（配对比较，同一折、同一验证集、同一 ρ̂）
A. 选中 (ξ̂,ρ̂) vs 同 ρ̂ 下最强 ξ 对手（“邻居”）：
   - 5/48 折差异显著（|t| > 1.96），全部是“选中 0.0005 显著优于 0.0010”：
     E0|2017/18  t = +2.06；SP1|2018/19 t = +2.84；F1|2019/20 t = +3.09；
     SP1|2020/21 t = +2.56；N1|2022/23 t = +2.23（t > 0 表示邻居更差）。
   - 中位 |Δlogloss| = 0.00141 nats，中位配对 SE = 0.00345 nats
     ⇒ 多数折的差比噪声小（中位 |t| = 0.42）。
B. 选中 vs 其余全部 29 个候选中最强的一个：0/48 折显著（最大 |t| = 1.00）。
   即换任何一组候选，验证集上都测不出差别。
结论：边界堆积不是“优化器没收敛”，而是**弱可识别**；但 5 折是真实偏好
（长记忆确实更好），不能用平局规则抹掉。

三、决策（方案 A）
**接受 33/48，不改选参规则；报告与附录中一律同时给出分布与配对 SE。**
- 不采用“平局规则取网格中心”：标准方向会让更多折滑向更小的 ξ，反而加重堆积。
- 不采用“全局固定 ξ = 0.0019”：等于放弃逐折调参，H2/H3 的选参红线会失去意义。
- 报告写法：给出 33/48 的分布 + 5/48 显著 + 邻居比较的配对 SE，并明确写
  “其余折的 ξ 在验证集上不可区分（中位 |Δ| < 中位配对 SE）”。

四、影响面
- `results/preds/preds_B4.csv`、`convergence.csv`、`xi_rho_by_block.csv`
  均按当前选参产出，无需重跑（B3/B4 汇总 log loss 0.9986 / 0.9939）。
- 下游 M2 配对推断不受影响（用的是预测文件，不是 ξ 本身）。
- 附录 A1 用固定 ξ = 0.0019、不挂 τ，与本决策独立。

六、复核订正（2026-11-24；阈值、选参规则与本文件产物均未改动）

1) 第三节「不采用平局规则取网格中心：标准方向会让更多折滑向更小的 ξ，反而加重堆积」
   这条理由**方向写反了**。0.0005 是网格最小端、0.0019 是中心，往中心挪应当**减少**
   堆积。正确理由应写成：「Occam 式平局偏向 ξ→0（无衰减 = 嵌套的 B3），那才会加重
   堆积；所以平局应偏向更长记忆一侧，而不是中心。」——结论（不采用平局规则）不变，
   但理由要按这个写，否则下一个读的人会照着反方向理解。

2) 第二节 B 的结论「5 折是真实偏好（长记忆确实更好）」属过度解读。5/48 在 5% 水平下
   期望本来就有 2.4 折，且全部同向；真正说明问题的是下面第 3 条的固定超参对照，
   不是那 5 折。

3) 新增证据（不改主结果）：同一份 train、同一套代码，**不做任何选择**，48 折全部用
   网格中心 (ξ=0.0019, ρ=0)，池化 test log loss **0.9903**，比逐折选中的 0.9939 好
   **0.0036**（90% 配对区间 [0.0013, 0.0060]，29/48 折更好）。另外两个固定配置
   (0.0019,−0.05)=0.9896 与 (0.0005,0)=0.9918 也都优于逐折选中。即：**逐折选参在
   当前验证窗口下是负收益**。根因是验证集只有 1 季（306–380 场）、相邻 ξ 真实差异
   ~0.001、配对 SE 0.0034，信噪比 0.3，argmin 近似抽签且系统性偏角落。
   产物：results/logs/b4_fixed_hp_{by_fold,contrasts,downstream}.csv
   命令：python -m src.models.sens_b4_fixed_hp

4) 三季验证集干跑（待签字口径，**未落地**）：验证集改为内层最后 3 季（中位 1,140 场），
   配对 SE 降到 0.0020、信噪比升到 0.95、池化 test log loss 0.99065，比交付版好
   0.0032（90% 区间 [−0.0069, −0.00002]）；但与固定中心相比差 0.0004（区间
   [−0.0018, +0.0023]，**含 0**）——扩窗只能「停止亏损」，不能带来正收益。
   产物：results/logs/b4_val3_window.csv；命令：python -m src.models.sens_b4_valwindow

5) ρ 边界堆积另有一条物理约束：τ(0,1)=1+λρ 与 τ(1,0)=1+νρ 必须为正，故
   ρ ≥ −1/max(λ,ν)。48 折实测物理下界在 −0.154 到 −0.278 之间，最紧的一折连
   −0.15 都贴着边界。把网格扩到 −0.35 并剔除不可行候选（2,304 个候选中 447 个被
   剔除，每折中位 9 个）后，12/48 折确实选了更负的 ρ（0 折反向），但池化 test log
   loss 反而**变差 0.0003**（18/48 折更好）。即边界堆积「部分是截断」，但往外扩
   不改善预测。产物：results/logs/b4_rho_extension.csv
   命令：python -m src.models.sens_b4_rho_grid

以上 3)–5) 全部是只读复核：不写 results/preds/、不改 convergence.csv、
不动 table_main.csv。要改口径须 M2 主签 + M5 会签。

1) 采纳：ξ = 0.0019（半衰期 ln2/ξ ≈ 365 天）、ρ = 0，48 折共用，不做任何在线选择。
   事前理由：0.0019 是预注册网格的中点，对应「一年」这一自然尺度；ρ = 0 是中性值，
   即关闭低比分修正。两数都不是在评估窗上挑出来的。
   效果：B4 pooled 0.9939 → 0.9903（−0.0036 [−0.0060, −0.0013]，30/48 折更好）。
   落地：tune_b4.fit_fixed()；run_b4.py 默认 --selection fixed。
         argmin 降级为 --selection argmin，产物写 results/logs/selection_diagnostic/，
         且用 tune_b4.LEGACY_FIT_OPTS 钉住历史容差 → 归档逐字节可复现（已实测）。

2) 否决：把验证集从 1 季扩到 3 季。
   3 季窗口 0.99064，比常量臂差 +0.00037 [−0.00177, +0.00234]，19/48 折更好。
   它确实把配对 SE 从 0.0034 压到 0.0020、信噪比从 0.42 抬到 0.96，但收益只到
   「停止亏损」为止，而代价是继续维护一条活的选参规则。A 落地后该规则没有存在理由。
   仅保留干跑证据 results/logs/b4_val3_window.csv。

3) 否决（旁支，如实披露）：ξ 取 0.0019 但 ρ 取 −0.05，pooled 0.9896，比报告臂低
   0.000665（90% 区间 [0.000262, 0.001067]，不含 0；18/48 折报告臂更好）。
   不采纳的理由不是「不显著」，而是：① 幅度是 ±0.02 等价边际的 1/30；
   ② 「因为它在这 16,733 场上更低所以选它」正是本次废除的那个错误，只是上了一层；
   ③ ρ = 0 才使 B3 → B4 成为单因素对照（只动时间权重），这是 §4.2 的核心表述。
