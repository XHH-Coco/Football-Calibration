## 1. 总体判断

方案的方法论骨架没问题。真正的问题分两类：

**第一类：把"预估"写成了"事实"。** 方案里有一批带 `≈` 的数值（行数、场次、B0 的 log loss、射门列覆盖），写的时候是按经验猜的。现在数据已经在仓库里（132 个 CSV、46,507 场），**猜的数有一半是错的**，而组员会把这些数当作"做对了长什么样"的自检标准。一个组员算出 1.074 却看到文档写"应该是 1.03–1.05"，只会怀疑自己写错了，然后把对的代码改成错的。这类错误比方法错误更危险，因为它直接摧毁自检机制。

**第二类：三条"看起来能自检、实际做不出来"的任务。** T3.2 的自检条件在数学上不成立；T1.6 的断言④会把每个赛季必然出现的升班马判成泄漏；H3a 用 8 个折点去讲"二十年趋势"。这三条的共同点是：**组员会照着做，然后在截止日前两天卡住**。

### 2.3 B0 基准的真实水平（这是最需要改的一处）

按"同联赛、严格更早赛季累积频率"计算，48 块逐块结果：

| 指标 | 数值 |
|---|---|
| **按场次加权 log loss** | **1.0743** |
| 逐块范围 | 1.0267（N1 1819）– 1.1151（F1 2021） |
| 全 1/3 预测的 log loss | 1.0986（= ln 3） |
| 比全 1/3 更差的块数 | **8 / 48**（法甲 2021 最差，1.1151） |

三个直接后果：

1. 方案 T4.1 写"log loss ≈ 1.03–1.05"，**实测均值 1.074、上界 1.115**。按原标准，一个完全正确的实现会被判成"做错了"。
2. B0 并不是稳赢"全押 1/3"。在 8 个块上它更差——因为联赛主胜率本身在漂移，用历史频率预测反而不如常数。**必须把 ln 3 单列为对照底线**，否则组员看到 B0 输给 1/3 会以为代码有 bug。
3. "低于 1.00 一定是泄漏"这句仍然成立（实测最低 1.0267），保留。

### 2.4 市场基准列的可行性

| 列 | 评估窗覆盖 | 首个 >90% 覆盖的赛季 |

## 3. P0 级问题（不改会让结论失效或任务做不出来）

### P0-1 M5 工时 64 小时，是其他人 1.7 倍

**位置**：§2 工作包表 + §3.5 标题 "34h + 统稿"

WP5（34h）+ WP6（30h）都挂在 M5 名下，实际 64h；其余四人 30/38/38/36。§2 结尾写"合计约 206 人时，人均约 41 小时"——**这个平均值是假的**，最大值是最小值的 2.1 倍。

**为什么必须改**：M5 同时是统稿人、幻灯片负责人、录像组织者，还要做 H2 全套校准分析。11/18 之后的 11 天里他会成为唯一瓶颈，而 §6 风险 #8 的兜底写的是"由备份人 M2 接管"——M2 自己的 WP2 是 38h，也接不住。

**改法**（v1.2 已落实）：

- WP6 中的**录像剪辑与素材整理**转给 M1（他本来就负责 `appendix.zip` 的封装，同一套工具链）。
- **H2b 的配对差计算与出图**转给 M2（T2.8 的主表里本来就有与 B6 的配对差，M2 只是多画一张图）。
- M5 保留：H2a 校准诊断、8 张图的图注与一句话结论、报告统稿、幻灯片内容、录像脚本与主讲分工。
- 修订后工时：M1 36 / M2 44 / M3 38 / M4 36 / M5 52，合计 206。**落差从 2.1 倍降到 1.4 倍**，且瓶颈从"一个人"变成"两个人都在 44–52h"。

### P0-2 T3.2 的自检条件在数学上不成立

**原文**：「单独喂一场比赛（权重=1）时，B4 与 B3 结果完全一致（说明补丁没破坏原模型）」

**问题**：单场比赛只能给出 2 个进球观测，而 B4 要估 `2N + 3` 个参数（N≈20 时为 43 个）。这不是"结果一致"，是**完全不可识别**，优化器会给出任意解，自检必然通过也必然无意义。

**改法**：「令 ρ = 0 且所有比赛权重 = 1 时，B4 的输出概率与 B3 在 1e-6 内一致」。这才是"补丁可退化回原模型"的正确检验——因为它检验的是**代码路径**，不是估计量。

### P0-3 T1.6 断言④ 会把每个赛季的升班马判成泄漏

**原文**：「test 里不存在训练期没出现过的队（升班马要在 train 里有记录，否则模型没法给分）」

**问题**：每个赛季每个联赛必有 3 支升班马，它们在历史训练集里**确实没有记录**。这条断言会在 48 块里大面积变红，而变红的不是错误，是足球的常识。更糟的是它与 §3.3 坑 4（「升班马在训练集里没有历史 → 用联赛新队平均值初始化 + 轻微 L2 收缩」）**直接矛盾**：坑 4 已经承认升班马会缺席，断言④却要求它必须出席。

**改法**：

- 断言改为：`test` 中出现的队伍，要么在 `train` 有历史，要么在 `new_team_flag` 列中被标记为 `True`；被标记的队伍数量应 **≤ 3 支/联赛/季**（法甲 2324、2425 为 18 队联赛，升班马数可能为 2）。
- 断言③（`n_train > 2000`）保留，实测最紧的一块是 N1 1718（前 14 季累计 4,000+ 场），余量充足。

### P0-4 B4→B5a 的"信息集相同"漏了样本权重

**原文**：T4.5「B4 能看到的只有"历史进球"和"谁强谁弱"，所以 B5a 的特征白名单只能是：双方滚动进球率、Elo 差」

**问题**：B4 不是普通极大似然，它是**加权**极大似然，权重 `w = exp(−ξ·Δ天)`。若 B5a 用等权训练，则 B4 与 B5a 的差同时包含"模型类别不同"和"样本权重不同"两个因素。**H1 的整个归因逻辑就此失效**——而 H1 是项目的核心贡献。

这是 v1.1 里最隐蔽也最致命的一处：白名单看起来管住了特征，实际上没管住权重。

**改法**（v1.2 已写入 T4.5）：

- B5a 训练时传入 `sample_weight = exp(−ξ̂·Δ天)`，`ξ̂` 取该折 B4 估出的 ξ（**只用该折 train 内部信息**，不能用未来折）。
- `feature_whitelist_b5a.csv` 增加一列 `sample_weight_rule`，写明权重来自哪一折的 ξ̂。
- 报告里明确写一句："B5a 与 B4 共享同一信息集与同一时间衰减权重，唯一差异是模型类别。"

### P0-5 H3a 用 8 个折点讲"二十年趋势"，分辨不出来

**原文**：T3.5「把每折估出的 γ 按赛季连起来，看二十年走势」

**问题**：48 折按赛季聚合只有 **8 个时间点**（1718–2425）。而且每折的 γ 是用"截至该季之前全部历史"估的，是一个不断加权的后验量，不是"该季的主场优势"。用它画趋势有两个毛病：点太少，且横轴语义错位。

**改法**（v1.2 已重写 T3.5）：

- **主分析**：逐季估 γ，得到 **22 个点**（2003/04–2024/25）。做法：对每个赛季 s，用截至 s 结束的加权历史拟合一次 B4（或固定折内超参），取出该窗口下的 γ_s；再用**样条/局部平滑**拟合 `γ ~ 年份`（第 5 讲方法），报趋势斜率与区间。
- **辅助核对**：8 个 fold 的 γ 单独列出，说明其与逐季序列同向，作为稳健性而非主证据。
- H3b 仍按**日期**切窗（不按赛季），这一点 v1.1 是对的，保留。
