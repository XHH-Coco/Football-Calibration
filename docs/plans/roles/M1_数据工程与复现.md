**本轮 4 条实测发现**

1. **队名写法跨季高度一致**。全库 243 个原始名，只有 **2 组**是同一队的不同写法（都在荷甲、赛季不重叠）：`Roda JC`→`Roda`、`Sparta`→`Sparta Rotterdam`。旧稿举例的 `Man United` / `Manchester Utd` 在本数据里**后者根本不存在**。归一后 241 个队名，归一把「改名被误判成升班马」从 **6,367 → 6,350** 场（少 17 场）。

### T1.2-a 参考实现（2026-11-08 全库 132 文件实测通过）

```python
import csv, io
from pathlib import Path
import pandas as pd

KEEP = ["Div", "Date", "HomeTeam", "AwayTeam", "FTHG", "FTAG", "FTR",
        "HTHG", "HTAG", "HS", "AS", "HST", "AST",
        "PSCH", "PSCD", "PSCA", "MaxCH", "MaxCD", "MaxCA"]

def read_raw(path: Path) -> pd.DataFrame:
    raw = path.read_bytes()
    try:
        text = raw.decode("utf-8-sig")          # 131 / 132
    except UnicodeDecodeError:
        text = raw.decode("latin-1")            # 实测仅 0405_E0.csv
    rows = list(csv.reader(io.StringIO(text)))
    header = [c.strip() for c in rows[0]]      # 去 BOM / 首尾空格
    data = [r for r in rows[1:] if any(c.strip() for c in r)]   # 丢 11 行全空白
    # 按列名取数：一次解决「行字段过多 / 表头重名 / 列缺失 / 两种表头变体」
    frame = pd.DataFrame({
        col: [r[header.index(col)] if (col in header and header.index(col) < len(r)) else ""
              for r in data]
        for col in KEEP
    })
    code = path.stem.split("_")[0]                        # "2425"
    frame["season"] = "20" + code[:2] + "/" + code[2:]  # "2024/25"
    return frame

panel = pd.concat([read_raw(p) for p in sorted(Path("data/raw").glob("*.csv"))],
                  ignore_index=True)
assert len(panel) == 46_507
panel["date"] = pd.to_datetime(panel["Date"], dayfirst=True,
                               format="mixed", errors="coerce")
assert panel["date"].notna().all()             # 实测 0 NaT
# 实际实现里 HomeTeam / AwayTeam 要先按 configs/team_alias.csv 归一
panel["match_id"] = (panel["Div"] + "|" + panel["season"] + "|"
                     + panel["date"].dt.strftime("%Y-%m-%d") + "|"
                     + panel["HomeTeam"] + "|" + panel["AwayTeam"])
assert panel["match_id"].is_unique            # 实测 0 重复
```

> 实测输出：46,507 行；`Div+season+Date+HomeTeam+AwayTeam` 五元组 **0 重复**；
> 日期范围 `2003-08-01 → 2025-05-25`；`FTR` 只有 `H/D/A` 三值。
> **不要用 `on_bad_lines='skip'`**：`0304_F1.csv` 会一次丢 365 行长度不齐的真实比赛（208 短 / 157 长），且不会报错。S1 的 `read_raw()` 已按名取列保住全部 380 场。

## 7. 坑位清单（14 条，都有人踩过）

1. **日期解析**。老文件是 `dd/mm/yy`，两位年份会被 pandas 猜成 19xx 或 20xx；`2024` 那种写成年的会被当 `2024-01-01`。**必须 `dayfirst=True` + 抽查每季首末期**，否则整个时间切分全错，而且错得很安静。
2. **队名不统一**（S2 实测订正）。真实改名只有荷甲的 `Roda JC`→`Roda` 与 `Sparta`→`Sparta Rotterdam` 两组；旧稿举的 `Man United` / `Manchester Utd`、`Ath Madrid` / `Atletico Madrid` 在本数据里**并不存在**。不归一 → 同一支队被拆成两队 → Elo 从 1500 重新开始 → M4 的 B1/B2 全乱，而报错信息里什么都看不出来；**反过来把同城不同队（`Ajaccio` / `Ajaccio GFCO`）误并成一支同样致命**。`team_alias.csv` 已于 **2026-11-10** 交付（比原定 11/08 晚 2 天），判定依据见 `configs/README.md`。
3. **编码**。别一律 `encoding='latin-1'`（utf-8 文件里的 é 会被读成 `Ã©`），也别用裸 `utf-8` 硬读（会崩在 cp1252 的 `0405_E0.csv`）。**按 `README §3.3`：先 `utf-8-sig`，报错再回退 `latin-1`**，并抽查 `Saint-Étienne`。
4. **不要为了"整齐"删赛季**。荷甲 2019/20 的 232 场、法甲 2019/20 的 279 场、法甲 2023/24 起的 306 场，都是**真实世界的结构变化**。删掉它们，附录 A1（γ 轨迹）就看不到 2020 空场期，H3 的逐块场次也对不上。
5. **数据冻结后不要再联网重下**。源站改一次版，数字就变了，而你不会收到任何提示。11/10 打 `data-v1.0` 标签之后，任何变更都要写 `docs/plans/CHANGELOG_data.md`。
6. **raw CSV 不是干净的矩形表**（2026-11-08 全量实测）。11 个文件行长 ≠ 表头（9 长 / 8 短，共 775 长行 + 1,331 短行）、14 个文件表头有重复列名、54 个文件完全没有 `PSCH/PSCD/PSCA` 列、7 个文件有 11 行全空白。裸 `pd.read_csv` 会在前两类上直接抛 `ParserError: Expected N fields` / `InvalidIndexError`；`on_bad_lines='skip'` 会**静默丢掉真实比赛**。按 T1.2-a 的 `csv.reader` + 按名取列白名单处理。**r2 实测补记**：775 条长行的 2,895 个溢出格 100% 为空串、1,331 条短行只缺空串列名列（白名单 0 截断）；`read_raw()` 现对「非空溢出」零容忍，见 §3.2.1。
7. **日期与键必须规范化**。`Date` 跨文件有 `dd/mm/yy` 与 `dd/mm/yyyy` 两种（**单文件内不混合**，73 个文件用两位年、29 个用四位年），`dayfirst=True, format='mixed'` 实测全库 0 NaT、范围 `2003-08-01 → 2025-05-25`。落盘 `date` 一律 ISO `YYYY-MM-DD`、`season` 一律 `YYYY/YY`；若 `preds_*.csv` 里写回原始 `dd/mm/yy` 字符串，跨模型按 `match_id` 内连接会全部对不上。
8. **默认解释器不是项目环境**（2026-11-08 S0 实测）。本机命令行 `python` 是 WorkBuddy 内置 3.13.14、无 pandas 等依赖；`import pandas` 会直接报 `ModuleNotFoundError`，看起来像「依赖没装好」，其实只是用错了解释器。跑 M1 脚本 / `pytest -q` 前先 `conda activate DSC5001_Project`，用 `python -c "import sys; print(sys.executable)"` 确认路径；Windows 也可直接用 `D:\Miniconda3\envs\DSC5001_Project\python.exe`。

9. **`matchday` 别只按主队分组**（2026-11-10 S2 实测踩过）。它是「该队本季已完成场次序号 + 1」，必须把 home / away **两队展开**成 2×46,507 行再按 `(league, season, team, date, 原始行序)` 累计，最后取主队侧；只按 `home` 单列算会漏掉该队的客场比赛，且不报错。另外 `is_promoted_*` 用「上一季名单」、T1.6 的 `n_new_team` 用「历史累积」，两者口径不同；评估窗都 ≤3，但全库 `I1 2004/05` 有 6 支新队（意甲扩军），**不要改断言去凑数**。
10. **别用模糊匹配自动并队名**（2026-11-10 S2 实测）。`Ajaccio` / `Ajaccio GFCO` 是同城两支不同俱乐部，`Man City` / `Man United`、`Bayern Munich` / `Munich 1860` 同理；全库 243 个名字只有 2 组是真实改名。反过来，不归一又会把 `Roda JC`→`Roda` 误判成升班马（本轮修掉 17 场）。判定依据与「不合并清单」在 `configs/README.md`，改映射必须走 PR + M4 会签。
11. **`date` 必须是 ISO 字符串，不能是 `datetime64`**（2026-11-10 S3 落地）。`preds_*.csv` 里 `date` 是字符串，`match_id` 是「`league|season|date|home|away`」逐字符拼出来的；panel 若存时间戳，各人读出来格式漂移，跨模型内连接会整片对不上且不报错。`build_panel()` 落盘前断言 `date.str.match(r'^\d{4}-\d{2}-\d{2}$')`，测试还造了一张伪 preds 表验证内连接逐行对齐。**同理不要为了「整齐」去重 `match_id`**——重复必须当场抛错，dedup 会静默少比赛。
12. **panel 里保留赛后列 ≠ 允许入模**（2026-11-10 S3 落地）。`FTR` / 比分 / 射门留在 22 列窄表里，是给 `y` 审计与误差分析用的；任何 B0–B5b 的特征都不得包含它们，三列收盘赔率除 B6/B6r 外同样不得入模（`data_interface.md` §2）。防泄漏由各 arm 的特征白名单 + `configs/splits.json`（S4 已交付）控制，不是靠「panel 里没有这一列」。另：`MaxCH/MaxCD/MaxCA` **不进 panel**，T1.4 覆盖率矩阵必须直接读 raw，从 panel 算根本看不到。
13. **48 折别自己按行号 / 按全库随机切**（2026-11-10 S4 落地）。train 的边界是「**同联赛 + `date < test_start`**」，不是「前 80% 行」、也不是「`season < 目标季` 的字符串比较」——后者只是等价复核，换数据一旦出现跨季日期重叠就会分叉，`make_splits()` 现在会直接抛错。M2 harness 必须统一调 `src.splits.resolve_split(panel, block)`；谁把 `test_start` 往后挪一天，模型就多吃一批本不该知道的比赛，而且 log loss 会「变好」得毫无破绽。同理，**不要按 16,733 场做 bootstrap**，重采样单位是 48 个块。
14. **入库边界别搞反，也不要手改契约**（2026-11-10 S4 落地）。`panel.parquet` **不入库**（同一脚本各自重跑），`configs/splits.json` **入库**（KB 级纯文本、必须逐字一致）。后者固定字段顺序、UTF-8 / LF、无时间戳，重跑 sha256 不变；`test_on_disk_contract_matches_regenerated` 会比对「磁盘契约 == 脚本重生成」，手工改一行就红。改切分口径必须走 PR + M2 主签 / M3·M4 会签，并在 `docs/plans/CHANGELOG_data.md` 登记重跑范围。

## 8. 你需要的术语（只列本岗要用的）

| 术语 | 人话 |
|---|---|
| SHA256 | 文件的"指纹"。同样的文件算出同样的值，用来证明"你和我下的是同一份数据" |
| rolling-origin | 用 2024 年之前的所有比赛训练、预测 2024/25，再往前滚一季，重复 8 次。**唯一不会用到未来信息的验证方式** |
| 泄漏（leakage） | 训练时不小心用到了预测时不可能知道的信息（比如用全场射门数预测这场胜负） |
| 簇（cluster） | 我们的一"块"＝ 一个 (联赛, 赛季)。统计上把它当作一个独立样本，48 块就是 48 个样本 |
| `latin-1` | 一种老编码，能正确读出西欧字符（é/ø/ß 不会变乱码） |
| `match_id` | 一场比赛的唯一身份证：`league\|season\|date\|home\|away`；`panel` 与各 `preds_*.csv` 用同一串，配对差靠它内连接 |
| ISO 日期 | `YYYY-MM-DD`。原始 CSV 是 `dd/mm/yy` 或 `dd/mm/yyyy`，落盘前必须转换 |
| 升班马 | 本赛季刚从低级别联赛升上来的队，历史数据里没有它；`is_promoted_*` 是 H3 的指示变量 |
| `matchday` | 该队本季第几场联赛。H3 用它识别「赛季前 6 轮」；只能由赛程 / 日期算，不能由结果算 |
| B6r | 市场 B6 经两参数重校准后的基准（参数只在 train 段拟合），H4 的工具 |
| 收盘赔率 | 比赛开始前最后一刻的赔率。它已经吸收了伤停、首发、临场资金，所以是"天花板" |
