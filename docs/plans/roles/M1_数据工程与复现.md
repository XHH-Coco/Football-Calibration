## 1. 你这个岗位在做什么（人话）

**你是给全组发牌的人。**

牌局要能打，前提是 52 张牌齐、不漏、没有两张重样的。你的活就是把 132 个散落的 CSV 收拾成一副干净的牌：**46,507 场**、每场一行、每行有日期有比分有收盘赔率、不重不漏。

这件事听起来像"跑个脚本"，其实不是。全组只有你真正知道数据的形状：

- 哪一列是哪一年才开始有的（射门数据不是一直都有）；
- 哪个赛季少了比赛（荷甲 2019/20 只踢了 232 场，法甲同季 279 场，都是疫情终止）；
- 法甲从 2023/24 起只有 18 队，所以那两季是 306 场而不是 380 场；
- `Man United` 和 `Manchester Utd` 是同一支队——**这个不统一，后面四个人的模型全废**。

报告里"46,507 场""评估窗 48 块 16,733 场""荷甲射门数据从 2017/18 起才有"这些话，都是你说出来的。**别人被问到数据细节答不上来时，只能找你——这就是你的不可替代性。**

你还有第二个身份：**复现负责人**。最后交上去的 `appendix/` 如果别人在干净电脑上跑不起来，前面 24 天白干。审稿人和老师不会跑你的代码，但"能不能复现"是评分表上明写的一条。

## 7. 五个坑（都有人踩过）

1. **日期解析**。老文件是 `dd/mm/yy`，两位年份会被 pandas 猜成 19xx 或 20xx；`2024` 那种写成年的会被当 `2024-01-01`。**必须 `dayfirst=True` + 抽查每季首末期**，否则整个时间切分全错，而且错得很安静。
2. **队名不统一**。`Man United` / `Manchester Utd`、`Ath Madrid` / `Atletico Madrid`。不统一 → 同一支队被拆成两队 → Elo 从 1500 重新开始 → M4 的 B1/B2 全乱，而报错信息里什么都看不出来。**这是全项目最贵的隐性 bug**，所以 `team_alias.csv` 归你，且要在 11/08 就交出去。
3. **编码**。别一律 `encoding='latin-1'`（utf-8 文件里的 é 会被读成 `Ã©`），也别用裸 `utf-8` 硬读（会崩在 cp1252 的 `0405_E0.csv`）。**按 `README §3.3`：先 `utf-8-sig`，报错再回退 `latin-1`**，并抽查 `Saint-Étienne`。
4. **不要为了"整齐"删赛季**。荷甲 2019/20 的 232 场、法甲 2019/20 的 279 场、法甲 2023/24 起的 306 场，都是**真实世界的结构变化**。删掉它们，附录 A1（γ 轨迹）就看不到 2020 空场期，H3 的逐块场次也对不上。
5. **数据冻结后不要再联网重下**。源站改一次版，数字就变了，而你不会收到任何提示。11/10 打 `data-v1.0` 标签之后，任何变更都要写 `CHANGELOG_data.md`。

## 8. 你需要的术语（只列本岗要用的）

| 术语 | 人话 |
|---|---|
| SHA256 | 文件的"指纹"。同样的文件算出同样的值，用来证明"你和我下的是同一份数据" |
| rolling-origin | 用 2024 年之前的所有比赛训练、预测 2024/25，再往前滚一季，重复 8 次。**唯一不会用到未来信息的验证方式** |
| 泄漏（leakage） | 训练时不小心用到了预测时不可能知道的信息（比如用全场射门数预测这场胜负） |
| 簇（cluster） | 我们的一"块"＝ 一个 (联赛, 赛季)。统计上把它当作一个独立样本，48 块就是 48 个样本 |
| `latin-1` | 一种老编码，能正确读出西欧字符（é/ø/ß 不会变乱码） |
| 升班马 | 本赛季刚从低级别联赛升上来的队，历史数据里没有它；`is_promoted_*` 是 H3 的指示变量 |
| `matchday` | 该队本季第几场联赛。H3 用它识别「赛季前 6 轮」；只能由赛程 / 日期算，不能由结果算 |
| B6r | 市场 B6 经两参数重校准后的基准（参数只在 train 段拟合），H4 的工具 |
| 收盘赔率 | 比赛开始前最后一刻的赔率。它已经吸收了伤停、首发、临场资金，所以是"天花板" |
