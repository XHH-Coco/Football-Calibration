## 1. 你这个岗位在做什么（人话）

**你是开另一辆车的人，而你的任务不是赢。**

如果你的 B5b 把博彩市场（B6）打败了，第一反应**不应该是庆祝，而是去查泄漏**。因为收盘赔率里已经吸收了伤停名单、首发阵容、临场资金流——这些东西你的特征表里根本没有，所以你不可能真的赢。赢了只有两种解释：数据漏了，或者代码错了。

你真正要交的是**两个数**：

| 差值 | 回答什么问题 | 怎么保证能回答 |
|---|---|---|
| **B4 与 B5a 的差** | 换成机器学习，值不值？ | 两边信息完全一样，**只换模型** |
| **B5a 与 B5b 的差** | 多喂信息，值不值？ | 模型完全一样，**只换信息** |

这两个差就是 **C1 / C2 受控比较**的全部内容（v1.3 起不再叫 H1）。所以**"特征白名单"是你最重要的产出，比模型本身重要**——因为模型谁都能调参，而"两边信息集是否真的相等"只有你能保证。

> ⚠️ **v1.1 漏了一半，你是唯一能补上的人**：B4 不是普通极大似然，它是**加权**似然（老比赛权重低）。所以 B5a 也必须传同样的 `sample_weight`。**只锁特征、不锁权重，B4 与 B5a 的差里就混进了第三个因素，C1 的归因直接失效。**

你还要顺手交三条可解释基线：B0（瞎猜）、B1（Elo）、B2（有序 logit）。这三条不是陪衬——B0 是"地板"，B1/B2 是"不用机器学习的诚实做法能到什么水平"。**如果 B5b 连 B2 都打不过，那"上更强的模型"这个默认假设就被你自己的数据推翻了**，这本身就是一个好结论。

## 3. 第一天 30 分钟：先把"地板"钉住

算两个数，它们会一直当你后面所有模型的参照：

```python
import math
print(-math.log(1/3))      # 1.0986  ← 全押 1/3
# B0：同联赛、严格更早赛季的经验频率 → 实测 ≈ 1.074
```

- **B0 = 1.074**（逐块 1.027–1.115）。这是地板，任何模型到不了 1.07 就是没学到东西。
- **全 1/3 = 1.0986**。注意：实测有 **8/48 块** B0 反而比 1/3 更差（最差 F1 2021 = 1.1151）。这不是 bug，因为联赛主胜率本身在漂移，用历史频率不如用常数。
- **B0 低于 1.00 = 一定泄漏**（用了当季信息）。

> v1.1 写的是"1.03–1.05"，那是估的，实测 1.074。别拿旧值当标准，否则你会把对的代码改错。

## 4. 任务清单

> **D1 决策（2026-11-08）：B5a / B5b 用 sklearn 内置 HGB，零新增依赖。**
> `sklearn.ensemble.HistGradientBoostingClassifier`（scikit-learn 1.9.1 已锁定），`loss='log_loss'`、`early_stopping=True`、**必须传 `sample_weight`**；`num_leaves`/`n_estimators` 对应改为 `max_leaf_nodes`/`max_iter`。
> **不装 LightGBM / XGBoost / CatBoost**，依赖总数仍是 8 个。C1/C2 锁的是「同一实现 + 同一权重 + 同一超参」，换用内置实现不改变归因逻辑。HGB 的 `predict_proba` 按 `classes_` 排，**落盘前必须重排成 `p_home,p_draw,p_away` 并写断言**。

### B2 的三个概率从哪来（一句话）

B2 先把所有输入压成一个数 η，再用**两个由数据估出的门槛** θ₁、θ₂ 把 η 切成三段：θ₁ 左边是客胜、中间一条带是平、θ₂ 右边是主胜。**那条平局带的宽度（θ₂−θ₁）是从数据里估出来的**，这正是它比 B1 强的地方——B1 只能算出"主队赢面多大"这一个数，再靠人为假设拆成三份。

### 关于"旅行距离"

需要 120 支队所在城市的经纬度，是隐藏工作量。**建议第一版直接不做。** 少一个特征不影响主结论；为了它拖垮 B5b 才致命。要做就在 11/17 之后有余量时补，并在报告里注明"作为增量实验"。

## 7. 五个坑

1. **滚动特征忘了 shift**。用了当场比分，log loss 会掉到 0.6 左右——一看就知道不对，但很难查是哪个特征漏了。**写完先做"打乱 y"测试**：如果打乱 y 后还能预测准，就是泄漏。
2. **Elo 更新顺序错了**（按周批量更新而不是逐场），信息会跨场泄漏。必须严格按日期逐场。
3. **队名没统一**，同一支队被拆成两队，Elo 全乱。**先找 M1 要 `configs/team_alias.csv`**，不要自己临时映射——你临时做一份，M1 做一份，最后两份不一致。
4. **B5a 只锁特征不锁权重**。这是 v1.1 的漏洞，也是最隐蔽的：白名单看起来完美，但 B5a 用等权、B4 用时间衰减，两者之差就不是"模型类别"的效应了，C1 归因失效。
5. **射门列在训练史早期缺失，不要插补成 0**。评估窗 48 块的射门数据 100% 可用（实测），所以这不影响 test；训练期缺失用"缺失指示列 + 该队历史均值"。**插补成 0 会被模型读成"这场一脚没射"，那是很强的错误信号。**

## 8. 你需要的术语

| 术语 | 人话 |
|---|---|
| Elo | 棋类积分。赢球加分、输球扣分，赢强队加得多 |
| 有序 logit | 承认"主胜 > 平 > 客胜"有顺序的回归，用一个 η 加两个门槛出三概率 |
| 比例优势 | 假设各协变量对"跨过每一个门槛"的作用相同。要检验（Brant test / 对比 multinomial） |
| 梯度提升 | 一堆小决策树接力纠错，每棵学上一棵的残差 |
| `HistGradientBoostingClassifier` | sklearn 1.9.1 内置的梯度提升实现；**B5a/B5b 唯一用它，不装 LightGBM**（D1，零新增依赖） |
| 早停 | 验证集不再变好就停，防止过拟合 |
| `sample_weight` | 每条样本的权重。用来表达"这场比赛更重要/更不重要" |
| 消融（ablation） | 一次去掉一个因素，看性能掉多少，从而归因 |
| 打乱测试 | 把标签随机打乱后重训，如果还能预测准，说明特征里有答案泄漏 |

## 9. 卡住了怎么办

| 卡点 | 先做什么 | 找谁 |
|---|---|---|
| B0 算出 0.9x | **立刻停**：查是不是把当季算进先验了 | M1（切分）/M2 |
| Elo 排序明显不合理 | 查队名统一表、查是否按日期逐场更新 | M1 |
| B2 系数符号反了 | 查类别编码顺序（必须 客=0/平=1/主=2） | 自查 |
| 特征表某列全是 NaN | 查该联赛该季是否本来就没这列（看覆盖率矩阵） | M1 |
| B5a 比 B4 好太多（Δ > 0.05） | 白名单有漏：逐列对照 B4 的输入 | M3 |
| B5b 比 B6 好 | **先查泄漏，别庆祝**：逐一检查 shift、Elo 顺序、有没有混入赔率 | M2 |
