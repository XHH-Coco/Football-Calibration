## 1. 你这个岗位在做什么（人话）

别人交的是零件：数据、模型、分数、区间。**只有你知道这些零件拼起来是一个什么论证**——

> 我们不是要打败市场。我们是要说清楚：**这些概率能信到什么程度，在哪个区域不能信，以及"换更强的模型"到底改变了什么。**

你有两个身份，都是硬活：

**① 校准诊断（H2a）——本项目最有洞察的部分。**
所有人都只报一个 log loss，而你能指出："模型在平局上系统性地过度自信（说 30% 实际只发生 25%），但在 5% 和 90% 这两个极端反而偏保守。" 这句话是**有形状的判断**，比"我们的模型 log loss 是 1.01"有价值得多。它回答的是"错在哪、为什么错"，而评分表里"误差分析"那一栏要的就是这个。

**② 统稿与呈现——没人替你兜。**
10 页幻灯、8 分钟录像、五个人出镜、11/29 提交。这件事的难点不在技术，在于**协调五个人的时间**，而你正好是唯一掌握全局视角的人。

> **v1.2 的工时调整请你先看**：v1.1 把 WP5(34h) + WP6(30h) 都压在你身上，实际 64h，是 M1 的 2.1 倍。v1.2 把**录像剪辑**给了 M1、把 **H2b 的数字和出图**给了 M2。你现在是 52h——仍然最多，但不再是"一个人卡住全队"。**H2b 你只写解读段，不再算数。**

## 7. 五个坑

1. **不定清单就开始画图**。最后会有 20 张图，报告只用 5 张，剩下 15 张的成本全是净亏损。**先写 8 行清单，让 M2 签字，再动手。**
2. **校准曲线用硬分箱**。10 个箱子连折线会制造锯齿，而这些锯齿会盖住真实形状（比如"平局在 20–35% 被高估"这个趋势会被切碎）。用局部平滑或样条。
3. **统稿时忍不住改别人的技术段落**。你改错了没人能发现，因为原作者以为你只是排版。**有疑问就问原作者，不要"顺手改对"。**
4. **录像拖到最后一天**。一定出问题：有人请假、设备坏、网卡、剪辑软件崩。**11/20 前把五人时间定死，11/26 开录。**
5. **结论是负结果就想"调一下阈值"**。回到 Proposal §5：负结果即成功，阈值 0.02 不可事后改。这一条你要是松口，整份报告的诚实性就没了，而"诚实呈现负结果"是评分表上明写的一条。

## 8. 你需要的术语

| 术语 | 人话 |
|---|---|
| 校准（calibration） | 你说 30% 的事，长期看是不是真的发生了 30% |
| 可靠性曲线 | 横轴 = 模型说的概率，纵轴 = 实际发生频率。完美校准就是对角线 |
| 过度自信 / 欠自信 | 说 40% 只发生 30% = 过度自信；说 10% 发生了 18% = 欠自信 |
| ECE | 把预测分箱，每箱"平均说的"与"实际发生的"之差，按箱大小加权平均。一个数概括校准 |
| 偏差（bias） | 预测概率减实际频率。正 = 说高了 |
| 局部平滑 / 高斯过程 | 不用固定分箱，用一个滑动的窗（或核）去估局部频率，曲线更接近真实形状（第 7 讲） |
| 样条 / GAM | 用分段多项式拼出一条光滑曲线（第 5 讲） |
| Murphy 分解 | 把 Brier 拆成校准、区分度、难度三块，让你能说"错在没校准"而不是笼统说"错" |
