## 0. 五分钟看懂这个项目（人话版）

### 0.1 一句话

每周有上千场足球比赛，博彩公司会为每场给出三个概率（主胜、平、客胜）。**我们不把市场当对手，而把它当最灵敏的测量仪器**：先审计它自己校准不校准（RQ1），再问一个只看赛前信息的透明模型能不能追上它、差距集中在哪、以及这个差距是「市场确实知道得更多」还是「价格里一个可修复的校准缺陷」（RQ2）。

### 0.2 为什么要关心足球

因为足球只是实验场，问题本身是通用的。保险定价、信贷审批、医疗辅助决策靠的都是"预测概率"而不是"预测类别"。一个分类还行、概率乱给的模型在这三个领域都是危险的。足球的好处是：每周有大量重复观测、结果干净、而且有一个**已知信息集**的极强外部预测者摆在那里，所以"差多少、差在哪"是可测量的。

v1.2 把项目讲成"检验上更强模型有没有用"，那只是阶梯里两级（C1/C2）能回答的事。**v1.3 的主线是审计市场**；模型阶梯是为回答 RQ2 提供受控工具，不是研究目的本身。

### 0.3 八级台阶：我们在比什么

`Team-32-Proposal_v3.0.md` §4 的 B0–B6（外加 B6r）不是一组模型堆在一起，而是一条**只允许一步改一件事**的楼梯：

| 台阶 | 人话解释 | 加了什么 |
|---|---|---|
| B0 | 瞎猜的基准：看历史上主胜/平/客胜各占多少，就按这个比例报 | 无 |
| B1 | 下棋那套积分（Elo）：赢球加分、输球扣分，强队分高 | 球队实力 |
| B2 | 一条能解释的回归：把"实力差、近期状态"压成一个数，再用两个**由数据估出的门槛**切成主胜/平/客胜三个概率。平局那条带的宽度是估出来的，不是人为设的（B1 做不到这一点） | 可解释性 |
| B3 | 把比赛拆成"主队能进几个球、客队能进几个球"，再算三种结果的概率 | 进球机制 |
| B4 | B3 加两个补丁：越久远的比赛权重越低 + 低比分（0-0/1-0/0-1/1-1）单独修正 | 结构正确性 |
| B5a | 用梯度提升（一堆小决策树接力纠错），但**只喂 B4 能看到的信息** | 换模型类别，不换信息 |
| B5b | 同样的梯度提升，**再喂上射门、休息天数、旅行距离等额外信息** | 换信息，不换模型 |
| B6 | 博彩市场本身（去掉抽水后的概率） | 天花板 |
| B6r | 把 B6 过一遍两参数重校准（只在 train 段拟合） | 检验「差距是信息还是校准」 |

**关键在两次"只改一件事"**：B4→B5a 只换模型、不换信息，所以两者之差 = "机器学习这种模型类别到底值不值"；B5a→B5b 只换信息、不换模型，所以两者之差 = "多喂信息到底值不值"。剩下没追上的差距，就是"我们确实没有博彩公司知道得多"（伤停、首发、临场消息），这部分本来就追不上。

> **⚠️ 阶梯里只有两级能做归因。** 上表看起来是一条连续楼梯，但 **B1→B2 同时改了估计原则（惯例设定 → 极大似然）和信息集（只用一个评分差 → 多个协变量）**，它是"两个并列的可解释基线"，不是单因素台阶。同理 B2→B3 也不是单因素。
> 因此报告里能写因果解释的**只有 B4→B5a 和 B5a→B5b 这两级**；B0–B2 只报各自的 log loss，谁低用谁，**不解释"为什么低"**。这一条被老师追问的概率很高。

### 0.4 四个赌注：H1–H4

> **口径变更（v1.3）**：对外假设一律用 `Team-32-Proposal_v3.0.md` 的 **H1–H4**。v1.2 的 H1/H2a/H2b/H3 全部降级，不再占用假设编号。

| 假设 | 人话 | 怎么算赢（预先写死） | 谁主责 |
|---|---|---|---|
| **H1** 市场自己校准吗 | 收盘价去抽水后「不够自信」：冷门给的概率偏高、热门给的概率偏低，校准斜率 > 1 | 比例法下去抽水的斜率 > 1，且 90% 区间下界 > 1；可靠性曲线**低概率区在对角线下方、高概率区在上方**（v3.0 已订正提交版写反的方向）。三法下「比例法偏差最大」需差值区间下界 > 0，否则只作描述 | M2 + M5 |
| **H2** 模型追得上吗 | B4（Dixon–Coles）打不过市场，而且差距不是小到可以忽略 | ① 95% 配对区间不排除 0 且不利于 B4；② 残差非零：90% 区间**不**整体落在 ±0.02 内；区间宽于 0.04 就只报估计、不宣称任何结论 | M2 |
| **H3** 差距在哪 | 差距集中在「有升班马」和「赛季前几轮」的比赛——这两处模型手里的实力信息最旧 | 两个指示变量 + 联赛-赛季固定效应回归，**两系数都为正且各自 90% 区间下界 > 0** 才支持；任一区间跨 0 就只作描述。1–3 / 1–6 / 1–10 轮次扫描是声明在先的**描述性稳健性曲线**，不进主推断 | M2 + M1 |
| **H4** 差的是信息还是校准 | 把市场重校准一遍（B6r）后，差距没缩小多少 → 我们输在信息，不在价格的校准缺陷 | 相对变化的 **90% 区间上界 < 25%** 才支持，下界 > 25% 则证伪；分母 gap < 0.01 nats 时改报绝对差并说明比例不稳定 | M2 |

**降级但不丢掉的三块**：

1. **C1 / C2 受控比较**（原 H1）。B4→B5a 只换模型、B5a→B5b 只换信息，两个差各配一个 ±0.02 的四分支判定（T2.7）。它们是**实验结果**，不是研究假设；负结果照样是有效结论。
2. **描述性误差分析**（原 H2a / H2b）。模型侧的可靠性曲线 / ECE / 偏差图支撑 H1 的解读；三种去抽水方法同号同量级是 H2 的稳健性检查。都不再做「假设是否成立」的宣称。
3. **附录 A1**（原 H3 主场优势）。γ 的 22 点逐季序列 + 样条趋势 + 空场期对照保留，但**降为附录稳健性分析**：2020–21 只有一个空场季，且同期有赛季腰斩、赛程压缩、换人规则变化，`06_评估 §2.4` 早已指出它是混杂不是干净的自然实验，不做因果主张。

> **阈值只有一条：等价边际 ±0.02 nats**（v1.2 的 H1 用 0.02，提交版 H2 用 0.01，v1.3 统一为 0.02，因为 48 簇下最小可检测差本身就是 0.02 量级）。所有判定规则在跑数前写进代码注释，事后不得修改；负结果即成功。

## 1. 术语人话对照表（看不懂原文时查这里）

| 术语 | 人话 | 为什么我们要它 |
|---|---|---|
| log loss（对数损失） | 你给真实结果的那个概率有多低，取对数后罚分。给 90% 却错了，罚得很惨；给 34% 错了，罚得轻。三个类别都算 | 这是我们的**主指标**。它同时惩罚"不准"和"乱自信"，是严格proper的 |
| 准确率（accuracy） | 猜对的比例 | **不用它**。足球顶天 50% 出头，准确率分辨不出模型好坏 |
| Brier score | 三个概率与实际结果的平方差之和 | 第二指标，跟 log loss 互为稳健性检验 |
| Murphy 分解 | 把 Brier 拆成三块：校准好不好（reliability）、有没有区分度（resolution）、比赛本身多难猜（uncertainty） | 让我们能说"错在没校准"而不是笼统说"错" |
| 校准（calibration） | 你说 30% 的事，长期看是不是真的发生了 30% | 本项目的核心概念 |
| ECE（期望校准误差） | 把预测按概率分箱，每箱里"平均说的概率"与"实际发生频率"的差，按箱大小加权平均 | 一个数概括校准好坏 |
| 可靠性曲线 | 横轴＝模型说的概率，纵轴＝实际发生频率。完美校准就是对角线 | 最能一眼看懂的图 |
| 过度自信 / 欠自信 | 说 40% 结果只发生 30%＝过度自信；说 10% 结果发生了 18%＝欠自信 | 描述模型侧校准误差的形状（H1 的辅助证据） |
| 去抽水（de-vig） | 博彩赔率含抽水，三个隐含概率加起来是 1.05 而不是 1，要按某种规则压回 1 | 不压回 1，就没法跟我们的概率比 |
| rolling-origin | 用 2024 年之前的所有比赛训练，预测 2024/25；再往前滚一季，重复 8 次 | 唯一正确的时间序列验证方式，防止"用未来预测过去" |
| 泄漏（leakage） | 训练时不小心用到了预测时不可能知道的信息（比如全场射门数去预测这场比赛的胜负） | 一旦泄漏，结果好得不像话，全部作废 |
| 簇 bootstrap | 有放回地重抽 48 个"联赛-赛季"块，每次重算结论，看结论抖不抖 | 给每个结论配一个区间，而不是只报一个数 |
| 等价性检验 | 不是"没测出差异"，而是"差异小到可以当一样"（**全项目统一 0.02**） | C1 与 H2 判据②都必须这么说，否则"没显著"什么都证明不了 |
| Dixon–Coles | 一个 1997 年的进球模型：每队有进攻力、防守力，主队有主场加成；再加"时间衰减"和"低比分修正" | B4 就是它，H2 的主模型 |
| ξ（xi） | 时间衰减速度。越大＝越只看近期 | B4 的第一个待调参数 |
| ρ（rho） | 低比分相关性修正。足球里 0-0、1-1 的实际频率比独立 Poisson 算出来的高 | B4 的第二个待调参数 |
| Elo | 棋类积分。赢了加分、输了扣分，赢强队加得多 | B1 |
| 有序 logit | 承认"主胜 > 平 > 客胜"有顺序的回归 | B2 |
| 梯度提升（GBM） | 一堆小决策树，每棵纠正前一棵的错；本项目统一用 **sklearn 内置 `HistGradientBoostingClassifier`**，不装第三方 GBM 库（D1） | B5a、B5b |
| 主场优势参数 γ | 主队进球期望的乘性加成。γ=0.2 表示主队多进约 22% | **附录 A1** 的描述性序列，不占假设编号 |
| 空场期对照 | 2020–21 赛季几乎没观众 | **附录 A1** 的对照窗口；同期混杂很多，只作描述，不称"自然实验" |
| 校准斜率 | 把 `logit(真实结果) ~ a + b·logit(预测概率)` 的 b 估出来；b>1 表示预测太保守（under-dispersed） | H1 的核心统计量；**b>1 时低概率区曲线在对角线下方** |
| design effect | 簇内相关让 48 块的有效样本量小于 16,733 场的程度 | 每个区间旁边都要报（W3） |
| 冷门–热门偏差（FLB） | 市场把冷门概率抬得太高、热门压得太低 | H1 的理论先验（Ali 1977；Cain et al. 2000） |
| B6r 重校准市场 | B6 过两参数 temperature-and-bias logit 映射；参数只在 train 段拟合 | H4 的唯一工具（提交版叫 `MK*`） |

### 3.4 M4 — 机器学习与特征（备份人：M3，工时 36h）

**人话定位**：**开另一辆车的人。**

你的任务**不是赢**。如果你的 B5b 把博彩市场（B6）打败了，第一反应不应该是庆祝，而是**去查泄漏**——因为收盘赔率已经吸收了伤停、首发、临场资金流，这些东西不在你的特征里，你不可能赢。

> **D1 决策（2026-11-08，v1.3-r2）：B5a / B5b 用 sklearn 内置 HGB，零新增依赖。**

> 落盘注意：HGB 的 `predict_proba` 列顺序按其 `classes_` 排，必须按 §5.3 / `data_interface.md` §1.1 重排成 `p_home, p_draw, p_away` 再写 CSV。

| T4.6 | **B5b：喂全特征**。同样的 sklearn HGB，加入 T4.4 的全部 6 类特征。**`sample_weight` 必须与 B5a 完全一致**（B5a→B5b 只许改信息，不许改权重，否则第二次单因素对照也失效）。调参用 M2 的内层验证：`max_leaf_nodes ∈ {7,15,31}`、`learning_rate ∈ {0.03,0.05,0.1}`、`max_iter` 用 `early_stopping=True` | 梯度提升（sklearn HGB）+ 早停 | 同上 | log loss 应略好于 B5a（预估好 0.005–0.02）；**若显著好于 B6，停下来查泄漏** |
| T4.7 | **做消融 + 特征重要性**：把 B4→B5a、B5a→B5b 两个差算出来，配一张特征重要性图（gain） | 消融分析 | `analysis/ablation.ipynb` | 两个差各一个数 + 区间（区间找 M2 要）；一句话结论："换模型带来 X，加信息带来 Y" |

**关于"旅行距离"**：需要球队所在城市的经纬度。这是隐藏工作量。**建议第一版不做**——先用手工填的 6 联赛约 120 队坐标表（每队一行，填城市经纬度），实在来不及就把这个特征砍掉，在报告里说明。少一个特征不影响主结论，但因为赶这个特征拖垮 B5b 才致命。

**交付物**：`src/models/b0_prior.py`、`b1_elo.py`、`b2_ordinal.py`、`b5_gbm.py`、`src/features.py`、`configs/feature_whitelist_b5a.csv`、`analysis/ablation.ipynb`、消融结果
（`configs/team_alias.csv` **由 M1 产出，你只消费**——v1.1 把它同时挂在 M1 和 M4 名下，v1.2 已归 M1）

**五个坑**

1. **滚动特征忘了 shift** → 用了当场比分，log loss 会掉到 0.6 左右，一看就知道不对，但很难查是哪个特征漏了。写完先做一次"只用特征预测、且把 y 随机打乱"的测试，如果还能预测准，就是泄漏。
2. **Elo 更新顺序错了**（比如按周批量更新而不是逐场），信息会跨场泄漏。
3. 队名没统一，同一支队被拆成两队，Elo 全乱。**先找 M1 要 `team_alias.csv`**。
4. **射门列的坑被 v1.1 夸大了**。实测：荷甲 `HS/HST` 从 2017/18 起满格，而 2017/18 就是评估窗第一季——**48 个 test 块里射门数据 100% 可用**，不需要"共同评估窗"。真正缺的只有训练史早期（2003/04–2016/17），处理方式是"缺失指示列 + 该队历史均值"，**不要插补成 0**（0 射门会被读成"没射门"，是强信号）。
5. 调参调出"很好看的数"时，先怀疑内层验证集是不是漏到了外层。

### 5.3 统一预测文件 schema（M2 定义，全员遵守）

| 列 | 类型 | 说明 |
|---|---|---|
| `match_id` | str | `league\|season\|date\|home\|away`，与 `panel.parquet` 一致，见 `data_interface.md` §1.0 |
| `league` / `season` | str | 如 `E0` / `2024/25`；`season` 一律 `YYYY/YY` |
| `date` / `home` / `away` | str | `date` 一律 **ISO `YYYY-MM-DD`**（不是 raw 的 `dd/mm/yy`）；队名已按 `team_alias.csv` 归一 |
| `model` | str | `B0`…`B5b`、`B6`、**`B6r`**（9 个 arm；M1–M5 是成员编号，永不作模型名） |
| `p_home` / `p_draw` / `p_away` | float | 和为 1（误差 < 1e-9） |
| `y` | int | 0/1/2 = H/D/A |

> 任何模型只要产出这张表，就自动进入评估框架，**不需要各自写评估代码**。这是全项目最重要的接口约定。
>
> **内部标签 → 落盘列序（v1.3-r2）**：各模型内部怎么给三分类编码都行（B2 有序 logit 常用 客胜=0 / 平=1 / 主胜=2，HGB 用 `classes_` 排序），但**写 CSV 前一律按 `classes_` / 门槛顺序重排成 `p_home, p_draw, p_away` 并写断言**；`y` 恒为 `H=0 / D=1 / A=2`。细则见 `data_interface.md` §1.1。

### 5.5 市场基准列口径（B6 唯一入口）

v1.1 在 T1.2 举例用 `B365H`，与 `README` §3.1、`data_interface.md` 的 `PSCH` 冲突。v1.2 统一为**收盘价 `PSCH/PSCD/PSCA`**，理由三条：① 与 Proposal 文字一致（closing odds）；② 实测评估窗 48 块中 45 块满格，另 3 块共缺 5 场（`1718_SP1` 1 / `1718_N1` 3 / `1819_D1` 1），**覆盖不输 B365**（B365 在 I1 2021、F1 2021 反而各有缺失）；③ 收盘价才是"信息已充分吸收"的那个时点，用它当天花板才有意义。

| 列族 | 含义 | 评估窗覆盖（实测） | 本项目用途 |
|---|---|---|---|
| `PSCH/PSCD/PSCA` | Pinnacle **收盘** | 45 块 100%；`1718_SP1` 1 / `1718_N1` 3 / `1819_D1` 1 共缺 5 场 | **B6 主基准（唯一）** |
| `PSH/PSD/PSA` | Pinnacle 开盘 | 覆盖好 | **不用**（时点不对，不是天花板） |
| `B365H/D/A` | Bet365，非收盘 | I1 2021、F1 2021 各缺 1–4 场 | **不用**（与 Proposal 口径不符） |
| `MaxCH/CD/CA` | 市场最高收盘 | 2019/20 起才有 | 只作稳健性，不作主基准 |
| `AvgCH/CD/CA` | 市场平均 | 2019/20 起才有 | 只作稳健性 |

> **一句话规则**：B6 只从 `PSCH/PSCD/PSCA` 三列算，缺就 drop（全窗只 drop 5 场，`n = 16,728`），**不许回填、不许换列**。回填会让 B6 与其他模型用的不是同一批比赛，配对差就失去意义。
>
> **B6r 的时点边界（v1.3 新增，防泄漏）**：B6r = B6 经两参数 temperature-and-bias logit 重校准；**两个参数只在该折的 train 段拟合，再应用到 test 段**，与 ξ/ρ/树深同样受 §5.1 调参红线约束。若在 test 段拟合，H4 会把「用答案改答案」误读成「校准缺陷被修复」。B6r 同样 drop 那 5 场，保持与 B6 同一批比赛。
>
> **B6r 的拟合样本边界（v1.3-r2 补充，必须写进实现）**：`PSCH/PSCD/PSCA` 自 **2012/13** 季才有，评估窗之前还有 9 个赛季的训练史完全没有收盘赔率。因此两参数**只用该折 train 段中这三列齐全的比赛拟合**（与 B6 同批 drop 规则一致，缺一即 drop、不回填），每折拟合样本数 `n_fit` 写进日志；test 段仍按 B6 的 16,728 场评估。若不设这条边界，各人实现会在「要不要把无赔率的历史比赛算进重校准」上分歧，H4 的分子分母都不可比。
